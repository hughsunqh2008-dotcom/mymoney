# mymoney

个人账目分析系统：导入银行账单 CSV → 自动分类 → 统计 → 生成报告与图表。

---

## 环境

- Python **3.13.15**，位于 `C:\Python`
- 虚拟环境在项目根目录的 `.venv/`（用 `Python: Create Environment` 建的，选了 3.13）

验证解释器是否选对：

```bash
python -c "import sys; print(sys.executable)"
```

输出路径里应该包含 `.venv`。

python mymoney.py --help          # 命令行帮助

python -m pytest -v              # 跑测试（用 python -m，不要直接敲 pytest）

## 设计决策

### 1. 金额用负数表示支出

- **选择**：保持银行原始数据的符号，不做转换
- **理由**：保留原始数据；算结余时直接求和即可
- **代价**：支出和收入的界限不清晰，判断"这是不是支出"要额外看符号

### 2. `uid` 用内容哈希生成

- **格式**：`日期_原始描述_金额(两位小数)_币种`
- **理由**：让"重叠导入"变得安全——先导入 1 月、再导入"1–2 月合并账单"时，1 月那部分会被识别为重复
- **代价**：见"已知限制"里的 uid 条

### 3. 日期存 `date` 对象，不存字符串

- **选择**：`Transaction.date` 是 `date` 对象
- **理由**：按月份分组、比较大小、算差值都天然支持，不用切字符串（切 `s[:7]` 取月份，遇到 `2026-1-3` 这种没补零的就会错）
- **代价**：JSON 序列化时要显式转换——`to_dict()` 用 `isoformat()`，`from_dict()` 用 `fromisoformat()`

### 4. 括号里含地点关键词才删

- **规则**：括号内容含 `店路街号城区广场中心支分店` 才删除整个括号，否则原样保留
- **理由**：地点不改变"这笔交易是什么"；但 `(已退款)` 这类信息改变了交易性质，不能删
- **代价**：关键词表是硬编码的，遇到"大道""商场"这类要手动加

### 5. 大小写不在清洗阶段处理

- **选择**：`normalize_description` 不动大小写，交给 `categorizer` 用 `.lower()` 两边比较
- **理由**：清洗不可逆，匹配可随时改规则。把问题放在影响面更小的地方
- **代价**：匹配层要记得两边都 `.lower()`，漏一边就失效

### 6. 规则冲突时按 JSON 顺序优先

- **选择**：遍历 `categories.json` 的顺序，先命中的分类赢
- **理由**：用户改 JSON 就能调优先级，不用改代码；行为可预测
- **代价**：依赖字典顺序（Python 3.7+ 有序，够用）

### 7. 金额为正的交易直接归为"收入"

- **选择**：`categorize` 第一步就判断 `amount > 0`，不看描述
- **理由**：退款场景——`"星巴克(已退款)"` 的描述里有"星巴克"，只按关键词会误归为餐饮
- **代价**：规则跑到代码里了，`categories.json` 改不了它。见"已知限制"

### 8. 同一批内完全相同的交易全部保留

- **选择**：`append_new` 只按"库里已有的 uid"去重，不检查批内重复
- **理由**：同一个文件里两行完全相同，比"同一笔被导出两次"更可能是真的发生了两次支付。多记一笔的代价是数字略高，少记一笔的代价是丢数据——数据丢失更难发现
- **代价**：**无法区分"两笔真实支付"和"同一笔被导出两次"**，且不会给任何提示
- **幂等性不受影响**：第二次导入同一文件时，所有 uid 都已存在，全部跳过
- **测试**：`test_append_new_keeps_identical_rows_in_same_batch`、`test_append_new_still_idempotent_with_duplicates`

### 9. 读银行 CSV 用宽容编码，写自己的 JSON 用标准编码

- **银行 CSV**：`utf-8-sig` → `gb18030` 依次尝试（外部文件可能带 BOM 或是 GBK）
- **自己的 `transactions.json`**：`utf-8`（无 BOM，别的工具读也不会出问题）
- **理由**：读外部文件要宽容，写自己文件要标准

### 10. 异常交易：单笔超过同分类"其他支出"平均值的 3 倍

- **规则**：`|tx| > 3 × (同分类其他单笔的平均值)`，交叉相乘写成代码是
  `|tx| × (n - 1) > 3 × (分类合计 - |tx|)`，其中 `n` 是该分类的笔数
- **不含自己**：算平均值时把正在判断的这一笔排除在外
- **理由**：含自己的话，一笔巨大的离群值会把它自己的平均值拉高，反而显得"正常"——离群值越极端，规则越抓不住它。排除自己之后，3000 元的房租对着 126.5 元的电费，阈值只有 379.5 元，藏不住
- **只有 1 笔的分类不参与**：没有"其他"，`n - 1 = 0` 会除以零；而且单笔交易本身没有可比对象
- **为什么交叉相乘**：写成除法会引入浮点误差和 `ZeroDivisionError`，两边同乘 `(n - 1)` 之后全是乘法
- **空结果是合法的**：这份数据按"含自己"的口径一笔都挑不出来。规则严格与否跟着数据走，不需要为了"有产出"去放松
- **2026-01 的结果**：房租 3000.00、高铁票 553.00（见"验收记录"）
- **测试**：`test_find_anomials_flags_the_outlier`、`test_find_anomials_excludes_self_from_average`、`test_find_anomials_jan_hand_checked`

### 11. 金额为 0 的行在解析阶段丢弃

- **选择**：`_parse_amount` 遇到 `0.00` / `-0.00` 返回 `None`，该行计入解析报告的"失败"
- **理由**：银行导出里的"余额查询""账户验证"这类行记 `0.00`，它没有金额信息，却会变成 `by_category` 里的一个分类（值 `0.0`）。结果就是 `stats["总支出"] == 0` 而 `cat_stats` 非空——`to_text` 算百分比时分母为 0，直接 `ZeroDivisionError`
- **不变式**：解析成功的交易 `amount != 0`。由此推出 **`cat_stats` 非空 ⇒ `总支出 > 0`**，所以 `reporter` 里不需要为除零做防御。不变式由 `test_parsed_amounts_are_never_zero` 守着
- **代价**：这类行会被算进"失败"，导入报告的失败数偏高。要区分"解析失败"和"无金额行"，得给 `parse_file` 的返回报告加一个 `跳过` 字段——那会改动契约，连带测试和模块 8
- **一句话**：脏数据在数据层拦，不在格式化层兜

## 遇到的问题

### `@classmethod` 的缺失

不加 `@classmethod` 时，`from_dict` 的第一个参数收到的是实例而不是类，无法用 `cls(...)` 构造并返回新对象。

### 正则跨过了括号，吃掉有意义的内容

- **现象**：`(退款)星巴克(国贸店)` 整个变成空字符串
- **我一开始以为**：把 `+` 改成非贪婪 `+?` 就够了
- **实际根因**：`+?` 只控制"吃多少"，不禁止"跨过某些字符"。`.` 本身能匹配括号，所以它会一直吃到能配上为止
- **解决**：把 `.+?` 换成 `[^（）()]+?`，用排除字符类明确禁止匹配括号
- **结论**：非贪婪 ≠ 不跨字符。要禁止跨字符必须用 `[^...]`

### 变量在 `if` 里赋值，`if` 之外使用会 NameError

- **现象**：解析没有"币种"列的文件时崩溃
- **根因**：`if currency_col: tx_currency = ...` 条件不成立时，变量从未被创建
- **解决**：`tx_currency = row[currency_col] if currency_col else None`
- **结论**：只要变量在 `if` 里赋值，用之前必须想清楚"没进 if 时它是什么"

### 判断解析失败时逻辑写反了

- **现象**：成功的行被丢弃，失败的行被当成功
- **根因**：写成 `if not parsed_row: 收下`。`not None` 是 `True`，所以 `None`（失败）进了成功列表
- **解决**：改成 `if parsed_row is None: 计入失败`
- **结论**：判断 `None` 要用 `is None`，不要用 `not`——`0`、`""`、`[]` 也都是假值

### 遍历字典时删除键会崩

- **现象**：`load_rules` 抛 `RuntimeError: dictionary changed size during iteration`
- **解决**：改成字典推导式 `{k: v for k, v in rules.items() if not k.startswith('_')}`
- **结论**：不要在遍历容器的同时修改它的长度

### `ensure_ascii` 拼错导致 `save_all` 完全不能用

- **现象**：`TypeError: JSONEncoder.__init__() got an unexpected keyword argument 'ensure_acsii'`
- **根因**：参数名少写了一个 `n`
- **结论**：报错说"不认识的参数"时，先对照函数签名检查参数拼写

## 已知限制

**输入格式**

- 对导入账单的格式规范要求高，列名必须在候选列表里
- 只尝试 `utf-8-sig` 和 `gb18030` 两种编码，都失败则报错
- 空行不计入"总数"（只统计非空数据行）
- 全角金额（如 `－38.00`）按解析失败处理，不做全角转半角
- 失败明细里记录的是"第几个数据行"，不是文件行号

**清洗**

- 括号里不含地点关键词的内容原样保留（如 `(已退款)`）
- 特殊符号（`*` `#` 等）不清洗
- 地点关键词是硬编码的，遇到"大道""商场"这类需要手动加
- 大小写不做归一化，靠匹配层忽略

**分类**

- 规则冲突时按 JSON 顺序决定，无法给单个关键词设优先级
- `amount > 0 → 收入` 硬编码在代码里，`categories.json` 改不了
- 因此"退款"这个关键词实际用不上；**负数的退款交易会被归成消费类**

**分析与统计**

- 异常检测只看支出；某分类只有 1 笔时永远不会有异常（没有"其他"可比）
- `category is None` 的支出在 `group_by_category` 里会同时落进 `"无类别"` 和 `None` 两个键，`by_category` 因此会输出两个键，同一笔钱在两边各算一次

**去重**

- 完全相同的两笔交易会生成相同 uid
- 批内重复全部保留，**无法区分"两笔真实支付"和"同一笔被导出两次"**
- uid 含金额，所以银行更正金额后会被当成新交易，导致重复计账

## 卡住时的排查顺序

1. 读报错信息，从第一行读起
2. 把报错关键词粘进搜索框
3. 在出错那行前面加 `print()`，看变量的实际值
4. 值不对 → 往回找"这个值是从哪来的"
5. 用断点：VS Code 里点行号左边设红点，F5 启动，单步走
6. 还不行 → 写 10 行以内的最小复现脚本
7. 这时候才去查书

各模块文件顶部的注释里写了对应的 Automate 章节号。
